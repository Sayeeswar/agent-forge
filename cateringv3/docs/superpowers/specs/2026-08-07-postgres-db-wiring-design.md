# Postgres DB Wiring — Design

Date: 2026-08-07

## Goal

Attach the already-installed local Postgres instance to the Reflex app: wire `db_url`,
generate + apply migrations from `cateringv3/models.py` (Customer, Order, OrderItem,
Payment — already written, untouched by this phase), and seed 500 rows per table for
testing. No state classes (AdminMenuState, AdminOrdersState, customer states) are
rewired to query the DB this round — that's a deliberately separate later phase (see
DECISIONS.md).

## Target DB

Local Postgres, already installed and running. Database `catering_db` already created
by the user. Credentials: user `postgres`, host `localhost`, port `5432`.

## 1. Config wiring

`rxconfig.py`: add `env_file=".env"` to `rx.Config(...)`. No `db_url=` kwarg — Reflex's
built-in env override (`Config.update_from_env()`, prefix `REFLEX_`) reads
`REFLEX_DB_URL` from `.env` automatically once `env_file` is set. Confirmed by reading
`reflex_base/config.py` directly (installed package, not docs) — no new pip dependency
needed (no `python-dotenv`), and `psycopg2` is already installed.

New root `.env` (gitignored, not committed):
```
REFLEX_DB_URL=postgresql+psycopg2://postgres:Sayeeswar@localhost:5432/catering_db
```

`.gitignore`: add `.env`.

## 2. Model registration

`cateringv3/__init__.py` (currently empty) gets one import line for `models` so
Reflex's SQLModel metadata registers `Customer`/`Order`/`OrderItem`/`Payment` before
`reflex db makemigrations` inspects the app. No other app files touched.

## 3. Migration

Run once, in order:
1. `reflex db init` — creates `alembic/` + config.
2. `reflex db makemigrations --message "initial schema"` — autogenerates migration
   from `models.py`. Inspect the generated script before applying (per Reflex docs).
3. `reflex db migrate` — applies it, creates the 4 tables in `catering_db`.

## 4. Seed data

`seed_data.py` (root, pre-existing, written by user) already matches `models.py`
schema column-for-column and inserts 500 rows into each of customers/orders/
order_items/payments, with consistent FKs and recalculated order totals. One fix
needed: its fallback `DATABASE_URL` has a placeholder host (`host`) — change to
`localhost`. Row counts (500 each) stay as-is, not changed.

Run: `python seed_data.py`.

## 5. Verification

- After migrate: confirm the 4 tables exist in `catering_db`.
- After seed: confirm row counts = 500 each, and one sanity join
  (order → items → payment) to confirm FKs line up.
- No UI/state changes this round, so no browser smoke test needed — that's the
  "full rewire" phase.

## Out of scope this round

- Rewiring `AdminMenuState` / `AdminOrdersState` / customer states off mock data onto
  real DB queries.
- Neon / prod connection string (local Postgres only, for now).
- Alembic migration edits beyond the initial autogenerated one.
